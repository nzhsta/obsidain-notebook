# 分布式训练与显存优化

## 大模型显存占用组成

> 来源：2026-04-18 对话归档

**问题/场景：**
训练大模型时，单卡显存往往不足以容纳模型状态，需要了解显存具体消耗在哪些地方。

**核心知识点：**
显存主要由两大部分构成：模型状态（Model States）和残余状态（Residual States）。

**1. 模型状态（约占训练显存的绝大部分）：**

| 组件 | 说明 | 显存估算（FP16/BF16 + Adam）|
|------|------|---------------------------|
| 参数（Parameters） | 模型权重 | 2Φ 字节 |
| 梯度（Gradients） | 反向传播产生的梯度 | 2Φ 字节 |
| 优化器状态（Optimizer States） | Adam 的一阶/二阶动量 + FP32 参数副本 | 12Φ 字节 |

- 使用 Adam + 混合精度训练时，总模型状态显存约为 **16Φ**（Φ 为参数量）。
- 示例：7B 模型训练需要约 112GB 显存（7×10⁹×16 ≈ 112GB），远超单卡 80GB 上限。
- 优化器状态是最大头，占总模型状态的 75%。

**2. 残余状态：**

| 组件 | 说明 |
|------|------|
| 激活值（Activations） | 前向传播中间结果，用于反向计算梯度。与序列长度 × batch_size × 隐藏层维度 × 层数成正比 |
| 临时缓存（Temporary Buffers） | 如梯度 all-reduce 时的 buffer |
| 不可使用碎片（Memory Fragmentation） | 显存分配导致的碎片 |

## DeepSpeed ZeRO 优化

> 来源：2026-04-18 对话归档

**问题/场景：**
单卡显存无法容纳大模型的完整训练状态（参数、梯度、优化器状态），需要分布式优化方案。

**核心知识点：**
ZeRO（Zero Redundancy Optimizer）的核心思想是**"谁用谁存"**，把优化器状态、梯度和参数分散到不同 GPU，消除冗余存储。

**1. ZeRO 三阶段对比：**

| 阶段 | 切分对象 | 显存节省 | 通信开销 |
|------|----------|----------|----------|
| **ZeRO-1** | 仅优化器状态 | 4× | 与数据并行相同 |
| **ZeRO-2** | 优化器状态 + 梯度 | 8× | 与数据并行相同 |
| **ZeRO-3** | 优化器状态 + 梯度 + **参数** | 与数据并行度 Nd 线性相关 | 增加参数 all-gather |

**2. 扩展技术：**

| 技术 | 原理 | 适用场景 |
|------|------|----------|
| **ZeRO-Offload** | 将优化器状态和计算卸载到 CPU 内存 + NVMe SSD | 单卡可训百亿模型 |
| **ZeRO-Infinity** | 扩展 Offload，支持 GPU、CPU、NVMe 三级存储 | 无限扩展超大模型 |

**3. ZeRO-3 的参数切片细节：**
前向/反向传播时，各 GPU 按需通过 `all-gather` 收集所需参数分片，计算完即释放。配合 Activation Checkpointing 可进一步降低激活值显存。

**4. 与其他优化技术的协同：**

| 技术 | 原理 | 效果 |
|------|------|------|
| 混合精度训练（FP16/BF16） | 前向/反向用 FP16，优化器用 FP32 | 参数/梯度显存减半 |
| 梯度累积 | 用小 batch 模拟大 batch | 减少激活值峰值 |
| Activation Checkpointing | 只存关键层激活，其余重算 | 以 20%-30% 计算换显存 |
| 流水线并行（PP） | 不同层放不同 GPU | 每卡只存部分层参数 |
| 张量并行（TP） | 单层内部分割（如列/行切分） | 单卡存更少参数 |

**5. 显存公式（启用 ZeRO-Offload）：**
单卡显存需求 ≈ 16Φ/Nd + activations + buffer

**6. 实际使用建议：**

| 模型规模 | 推荐配置 |
|----------|----------|
| < 1B，单卡可放下 | 直接使用 FP16 |
| 1B ~ 10B，多卡可用 | ZeRO-2 + Activation Checkpointing |
| 10B ~ 100B | ZeRO-3 + Offload（CPU）|
| 100B+ | ZeRO-Infinity（NVMe）+ 3D 并行 |

## 数据并行（Data Parallelism, DP）

> 来源：2026-04-18 对话归档

**问题/场景：**
如何理解分布式训练中最基础的数据并行，以及它与 DeepSpeed ZeRO 的关系。

**核心知识点：**
数据并行是**最基础、最常用**的分布式训练方式。核心思路：**每个 GPU 都存一份完整的模型，但输入数据被切成 N 份，各 GPU 独立计算，最后把梯度汇总同步。**

**1. 工作流程：**

| 步骤 | 各 GPU 行为 |
|------|------------|
| 1. 分发数据 | 全局 Batch 被切成 N 份，每卡拿到一份 |
| 2. 独立前向传播 | 每卡用自己的数据计算 loss |
| 3. 独立反向传播 | 每卡计算出各自的梯度 |
| 4. 梯度同步（All-Reduce） | 各卡梯度求平均，保证参数更新一致 |
| 5. 更新参数 | 每卡用同步后的梯度各自更新（结果相同）|

**2. 关键的通信操作：All-Reduce**
- Ring-AllReduce：把 N 个 GPU 排成环，梯度分块传递，总通信量约 2 × 模型大小
- 本质：每张卡最终得到所有卡梯度的平均值 (1/N)Σgi

**3. 数据并行 vs 其他并行方式：**

| 并行方式 | 切分对象 | 每卡存多少模型 | 适用场景 |
|----------|----------|----------------|----------|
| **数据并行（DP）** | **数据** | 100% 完整模型 | 模型能放进单卡时，最省心 |
| **模型并行（MP）** | **模型参数** | 部分层/参数 | 模型太大，单卡放不下 |
| **流水线并行（PP）** | **网络层** | 若干连续层 | 层数很多的大模型 |
| **张量并行（TP）** | **单层内的张量** | 单层的一部分 | 单层参数量过大 |
| **ZeRO** | 数据 + 优化器状态 + 梯度 + 参数 | 按需动态收集 | 超大模型训练 |

**4. 数据并行的致命前提与问题：**
- **前提**：模型必须能完整放进单张 GPU
- 7B 模型用 FP16 需 14GB 存参数，但加上梯度 + Adam 状态需 ~112GB，远超 A100 80GB 上限 → **传统 DP 直接失效**

**5. DeepSpeed ZeRO 与数据并行的关系：**
- **ZeRO 本质上是一种"升级版的分布式数据并行"（DDP）**
- 仍然基于数据并行的思想（数据切分、独立计算），但通过把模型状态也分布式存储，突破了"单卡必须装下整个模型"的瓶颈

| | 传统 DP | ZeRO |
|--|---------|------|
| 模型存储 | 每卡存完整模型 | 参数/梯度/优化器状态 **切分到各卡** |
| 通信量 | 仅 All-Reduce 梯度 | All-Reduce + All-Gather + Reduce-Scatter |
| 显存效率 | O(Φ) 每卡 | O(Φ/N) 每卡 |
| 代码改动 | 几乎无 | 几乎无（DeepSpeed 封装）|
