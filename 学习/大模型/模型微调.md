## 1.1 lora
- 秩
	- 推荐秩
		- 32
	- 缩放系数
		- 64（秩的 2 倍）
- Qlora
	- 节省显存（把显存给到批次大小和秩上，提升效果）
	- 量化等级
		- 4
## 1.2 评估标准
- 生成式模型评估主流方法
	- 主观评估
		- 通过核心问题对模型提问，人为评估（**主流**）
	- 客观评估（非主流）
		- 通过一些具体的评估指标来判定模型**输出的内容**与**标准答案**之间的**相似度**
		- <font color="#ff0000">文本命中率</font>
- 验证集评估
	- 不是很关注验证数据的效果，验证集的 loss 一般呈现上升-->平缓-->下降
	- 法律、医疗行业，这种<font color="#ff0000">用词规范</font>的行业，需要要求验证集的效果（答复和标签之间的相似度足够高）
	- 其他行业，可能需要模型有一方面的自我发挥（验证集的 loss）不需要特别要求
- **如果验证集和训练集的表达方式（数据分布、格式、语言风格、任务表述等）不一致，验证集的 loss 很可能降不下来**，即使训练集 loss 正常下降，模型在验证集上表现也会很差。这种现象通常不是模型“学不好”，而是**验证集和训练集之间存在“分布偏移”或“语义鸿沟”**

## 1.3 量化
- 微调量化
	- Qlora，参数量化后，仍然在进行**动态训练**，因此对于模型精度的影响很小
	- 量化的精度损失，可以通过模型训练弥补回来
	- Qlora 节省显存，可以适当提升批次样本数量，批次样本越大越好，精度降低的影响很小
	- 只在训练过程中进行量化，训练完成后进行反量化操作，所以模型的<font color="#ff0000">导出数据类型是不变</font>的
- 导出量化（<font color="#ff0000">不推荐</font>）
	- 已经训练完成，并测试通过，要对模型导出部署时
	- 最早出现在小模型的工业化落地，任务场景单一，即使牺牲精度也可以保证效果
	- 一般来讲，导出量化是<font color="#ff0000">牺牲</font>模型的<font color="#ff0000">精度</font>来**提升模型的推理速度**
	- 场景
		- 对模型的精度要求不高，且需要压缩硬件成本

Ollama 社区上的模型基本都是经过导出量化，所以都是个人用户在用

# 2 不同框架微调、部署差异解决
- 原因
	- Llama-factory 框架的<font color="#c00000">对话模板</font>与**大模型自带的对话模板**是不同的

## 2.1 对话模板
`Tokenizer_config.josn `文件内存在 chat_template 
- 定义角色（系统、用户）
- 定义了生成模型**以何种方式**进行回复
- 不同框架、模型的对话模板**不一致**,各个框架为了高度集成各个模型（集成各个模型的数据处理方式），它定义了一些通用模型的对话模板

## 2.2 解决方法
- vllm 支持使用自定义模板[[【资料】vllm与LMDeploy如何自定义对话模板.pdf]]
- 为了使语言模型支持聊天协议，vLLM 要求模型在其 tokenizer 配置中包含聊天模板。聊天模板是一个 Jinja2 模板，用于指定角色、消息和其他特定于聊天的 token 如何在输入中编码.
	```shell
	vllm serve <model> --chat-template ./path-to-chat-template.jinja
	```

这里的`jinja`文件需要自己生成，生成方式如下：
```python
# mytest.py
import sys
import os

# 将项目根目录添加到 Python 路径
root_dir = os.path.dirname(os.path.dirname(os.path.dirname(os.path.dirname(os.path.abspath(__file__)))))
sys.path.append(root_dir)

from llamafactory.data.template import TEMPLATES
from transformers import AutoTokenizer

# 1. 初始化分词器（任意支持的分词器均可）
tokenizer = AutoTokenizer.from_pretrained("/root/autodl-tmp/llm/deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B")

# 2. 获取模板对象
template_name = "qwen"  # 替换为你需要查看的模板名称
template = TEMPLATES[template_name]

# 3. 修复分词器的 Jinja 模板
template.fix_jinja_template(tokenizer)

# 4. 直接输出模板的 Jinja 格式
print("=" * 40)
print(f"Template [{template_name}] 的 Jinja 格式:")
print("=" * 40)
print(tokenizer.chat_template)
```

微调只是让模型具备处理特定问题的能力，所以微调所调整的只是模型的很小的一部分知识，所以它更容易受到一些因素的影响（对话模板）
