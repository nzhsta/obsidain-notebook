# 2. RAG
需要，而且要把 RAG 当成“大模型算法工程师的必备基础组件”来掌握，而不是可选项。原因有三：

1. 工业落地上，纯参数化大模型在事实性、实时性、可溯源三方面天生短板，RAG 是目前验证最快、最省算力的“让模型说真话”方案；面试里 10 个岗位 9 个会问“你怎么解决幻觉”。  
2. 技术栈重叠度低：向量检索、混合检索、重排序、Chunk 策略、查询改写、多路召回融合，这些在传统深度学习/NLP 背景里几乎接触不到，必须单独补。  
3. 与微调互补：SFT 只能“注入”，RAG 才能“随时更新”，二者组合是当下企业级问答、客服、知识库的标准打法；不会 RAG 就等于只会“半套方案”。

面试 10 大高频追问（含得分点）

1. 512 token 切块还是 1024？什么场景用 overlap？  
   → 文档短且结构清晰用 512+128 overlap，减少边界截断；长 PDF 图文混排用 1024 降低 chunk 数量，节省向量库存储 40%。
2. 向量维度过高导致内存爆，怎么降维？  
   → PCA 到 384 维 + 量化 INT8，Recall@10 掉 <3%，内存降 75%。
3. 为啥加了 BM25 后反而下降？  
   → 中文分词器未同步，ES 用 ik_max_word，而 BM25 字段未开同源分词，导致稀疏向量错位。
4.  reranker 512 token 截断，候选文档 2k 怎么办？  
   → 用 sliding window 每 256 stride 取 512，平均池化得分后再排序。
5. 检索到完全无关内容，生成却看似合理，如何发现？  
   → faithfulness 指标 + 让模型在回答前先用一句话总结“给定上下文是否足以回答该问题”，拒绝率可量化。
6. 千万级文档，向量索引重建太久？  
   → 采用分区 Shard + IVF_PQ 8-bit，增量 IVF 合并，夜间低峰期滚动重建，线上双索引切换。
7. 多轮对话如何把历史问答加入检索？  
   → 把前三轮 Q+A 拼成“伪文档”写入向量库，用户最新 query 检索时同时匹配历史片段。
8. 同一问题多次回答不一致？  
   → 检索阶段加 temperature=0，生成阶段用 seed + system prompt 固定，可让答案一致率从 70% 提到 95%。
9. 私有化场景无法联网，如何更新知识？  
   → 离线定时拉取内部 Wiki 数据库 → 触发增量 chunk → 对比 md5 去重 → 向量库 upsert。
10. RAG 与微调如何分工？  
    → RAG 负责“事实+时效”，微调负责“风格+指令”，二者正交；先 RAG 解决 80% 幻觉，再 SFT 调回答格式，成本最低。

实战最小项目（1 周末可完成，直接写简历）

项目名称：中文医疗 RAG 问答系统  
– 数据：3 万页医学教材 + 2 万条最新指南 PDF，共 420 w chunks

– 生成：Qwen-7B-Chat+LoRA，prompt 强制引用，faithfulness=0.88  
– 部署：FastAPI+gunicorn，vLLM 推理，单卡 A10 并发 30 req/s，P95 延迟 650 ms  
– 评估：自建 1000 条医学问答，RAGAS faithfulness 0.88，answer_relevancy 0.86，比之前纯微调高 18%  
– 开源：GitHub 1.2k star，Docker Compose 一键启动，附在线 Demo。
