### 2.1.1 第一部分：不同任务该选什么微调方式？

微调方法的选择核心在于：**你需要模型改变什么？** 是改变它的“说话方式（格式）”，还是改变它的“知识储备”，或者是“推理逻辑”。

#### 2.1.1.1 场景一：垂直领域知识注入 (Domain Knowledge Injection)
*   **任务举例**：法律文书撰写、医疗诊断辅助、公司内部私有知识库问答。
*   **特点**：模型原有的参数中不存在这些知识，或者知识记忆模糊。
*   **推荐策略**：
    *   **首选**：**全量微调 (Full Fine-tuning)**。如果算力允许，这是注入知识最彻底的方法。
    *   **高性价比**：**QLoRA (Target All Linear Layers)**。
        *   *关键点*：必须针对所有线性层（Attention + FFN）进行微调。仅微调 Q、V 对知识注入效果很差，因为知识主要存储在 FFN（前馈神经网络）中。
        *   *Rank 设置*：需要较高的 Rank (r=64, 128 甚至 256)。低 Rank 即使拟合了训练数据，也往往是“死记硬背”，泛化性差。

#### 2.1.1.2 场景二：格式规范与风格迁移 (Format/Style Transfer)
*   **任务举例**：让模型输出 JSON、SQL 语句、扮演特定角色（如“猫娘”）、摘要生成。
*   **特点**：模型本身懂得语言和逻辑，只是不知道你想要的输出格式。
*   **推荐策略**：
    *   **首选**：**LoRA (Standard)**。
    *   *关键点*：通常只需要微调 Attention 层的 `q_proj`, `v_proj` 即可，或者加上 `k_proj`。
    *   *Rank 设置*：低 Rank (r=8, 16) 足够。过高的 Rank 反而容易过拟合，导致模型只会输出 JSON 而丧失了通用的对话能力。
    *   **备选**：**P-Tuning v 2 / Prefix Tuning**。对于极少样本（Few-shot）的格式对齐，Prompt Tuning 类的软提示微调有时候效果出奇的好，且参数量极小。

#### 2.1.1.3 场景三：逻辑推理能力增强 (Reasoning Enhancement)
*   **任务举例**：复杂的数学题（CoT）、代码逻辑修复、Agent 规划。
*   **特点**：这是最难的。单纯的 SFT（有监督微调）往往只能让模型学会“模仿推理的步骤”，而不是真正学会“推理”。
*   **推荐策略**：
    *   **SFT + DPO/PPO**。仅仅靠 SFT 很难提升逻辑上限。通常需要先用 SFT 甚至 LoRA 让他学会输出 CoT 的格式，然后必须接入 **RLHF (如 DPO - Direct Preference Optimization)**。
    *   **数据为王**：这里微调方式不重要，重要的是数据质量（必须包含详细的推理步骤）。

### 2.1.2 第二部分：结合任务结构的 LoRA 插入位置与策略

这是你问题的核心技术点。LoRA (Low-Rank Adaptation) 的本质是在原有权重 $W$ 旁路增加 $\Delta W = B \times A$。

#### 2.1.2.1 LoRA 插在 Attention 还是 FFN 更合适？
**结论**：**成年人全都要（Target All Linear Layers）是目前的 SOTA（最佳实践）。**

*   **Attention ($W_q, W_k, W_v, W_o$)**：
    *   **作用**：控制“注意力”分配，即模型该看哪里。
    *   **适合任务**：需要捕捉上下文依赖关系的任务（如摘要、长文本理解）。
    *   **早期观点**：最早的 LoRA 论文主要针对 `q_proj` 和 `v_proj`。这对于改变模型的“关注点”很有效，适合风格迁移。

*   **FFN (MLP / $W_{gate}, W_{up}, W_{down}$) - 关键所在**：
    *   **作用**：根据 Transformer 的机制研究（如 Meng et al., 2022 的 ROME 论文），FFN 层被认为是**存储事实性知识（Key-Value Memories）**的主要区域。
    *   **数据表现**：QLoRA 论文（Dettmers et al., 2023）实验表明，只微调 Attention 层的效果远不如同时微调 Attention + FFN。
    *   **案例**：在医学微调任务中，如果不微调 FFN，模型可能学会了医生的语气，但开出的药方全是通用的（比如“多喝热水”），只有微调 FFN，才能让其根据症状关联到具体的特异性药物。

#### 2.1.2.2 动态 Rank 与 AdaLoRA
**问题**：所有的层都需要同样的 rank (比如 r=16) 吗？
**答案**：不需要。不同层对任务的贡献度不同。

*   **AdaLoRA (Adaptive LoRA)**：
    *   **原理**：它根据权重矩阵的奇异值（SVD）重要性，动态分配 rank。对于重要的层，给更高的 rank；不重要的层，给低 rank 甚至裁剪掉。
    *   **优势**：在参数总量不变的情况下，AdaLoRA 通常比标准 LoRA 效果更好。
    *   **策略建议**：如果你不知道哪一层重要，使用 AdaLoRA 或者类似的动态剪枝策略。通常来说，**靠近输出层的参数往往对特定任务更敏感**，而底层的参数更偏向通用的语法特征。

#### 2.1.2.3 层级 LoRA (Layer-wise LoRA) 策略
*   **底层 (Lower Layers)**：负责词法、语法、浅层语义。
    *   *策略*：如果你只是做简单的文本分类或格式转换，可以冻结底层，只微调高层，节省显存。
*   **高层 (Upper Layers)**：负责抽象语义、逻辑推理、知识融合。
    *   *策略*：对于复杂的逻辑任务或知识注入，高层的 LoRA Rank 应该设置得更大，或者给予更大的学习率（Layer-wise Learning Rate Decay 的反向应用）。

### 2.1.3 第三部分：多任务共享 + 任务专属 Adapter

在实际生产（如 SaaS 平台或综合 Agent）中，我们往往希望一个模型能干多件事。

#### 2.1.3.1 架构设计：Shared Trunk + Branch Adapters

1.  **Shared LoRA (通用底座增强)**：
    *   在一个大规模的混合数据集（Instruction Tuning Data）上训练一个通用的 LoRA 模块。
    *   **目的**：让模型更听话，理解指令，作为一个增强版的 Base。

2.  **Task-Specific LoRA (任务专家)**：
    *   针对特定任务（如“写 SQL”、“翻译”、“医疗问答”）训练独立的小 LoRA。
    *   **Rank**：这些专属 LoRA 的 Rank 可以很小 (r=8)。

#### 2.1.3.2 动态路由与混合 (LoRA-Hub / MoE-LoRA)
*   **线性加权**：推理时，权重 $W' = W_{base} + \alpha_1 \cdot LoRA_{shared} + \alpha_2 \cdot LoRA_{task}$。
    *   *风险*：直接相加可能会导致参数冲突（Interference），导致模型输出乱码。
*   **LoRA 作为路由专家 (MoE)**：
    *   使用一个小的 Router 网络（Classifier），根据用户输入的 Prompt，动态决定激活哪一个 LoRA Adapter。
    *   **案例**：用户问“帮我写个 Python 脚本”，Router 激活 `Coding_LoRA`；用户问“合同怎么写”，Router 激活 `Legal_LoRA`。这是目前企业级应用最稳健的架构。

### 2.1.4 第四部分：微调失效的原因深度解析（避坑指南）

很多时候微调失败不是算法问题，是细节问题。

#### 2.1.4.1 虚假的 Loss 下降 (Distribution Shift)
*   **现象**：Training Loss 一路狂跌，Validation Loss 也不错，但生成出来的东西就是不说人话，或者只会重复输入。
*   **原因**：
    *   **Prompt 格式错误**：训练时的 Prompt Template（如 `<|user|>...<|assistant|>`）和推理时即使有一个空格的差别，都会导致模型崩溃。这是最常见的原因。
    *   **EOS Token 缺失**：训练数据里没有加 `<EOS>`（结束符），导致模型学会了永远不停止说话，直到最大长度。

#### 2.1.4.2 灾难性遗忘 (Catastrophic Forgetting)
*   **现象**：微调完医疗模型后，问它“你好”，它回答“建议服用阿莫西林”。通用能力丧失。
*   **原因**：领域数据密度过高，改变了参数分布的重心。
*   **解法**：
    *   **数据混合 (Replay)**：在微调数据中，混入 10%-20% 的通用对话数据（如 Alpaca, ShareGPT）。这是**必须**做的。
    *   **减小 Rank**：限制模型改变的幅度。

#### 2.1.4.3 过拟合与幻觉增强
*   **现象**：模型对训练集里的问题回答得完美，稍微改一个字就开始胡说八道。
*   **原因**：数据量太少（比如只有 100 条），但 Epoch 跑了太多（比如 10 个 Epoch），或者 Rank 太大（r=64）。
*   **经验法则**：对于 < 1000 条的数据，Epoch 不超过 3-4，Rank 建议 8 或 16，Dropout 设为 0.05 或 0.1。

#### 2.1.4.4 评估错位
*   **现象**：用 BLEU/ROUGE 分数看微调效果很好，人工看很差。
*   **原因**：生成式任务不能只看 n-gram 重叠。
*   **解法**：使用 **LLM-as-a-Judge**。让 GPT-4 对微调后的模型输出进行打分，或者建立特定任务的测试集（Test Set）计算准确率（如代码通过率、选项正确率），而不是文本相似度。

### 2.1.5 总结建议

如果你现在要开始一个新任务：

1.  **策略**：先用 **QLoRA**，目标模块选 **All Linear** (Attn + FFN)。
2.  **配置**：Rank 起手 **32** 或 **64**，Alpha 设为 Rank 的 2 倍（即 64 或 128）。
3.  **数据**：准备高质量数据，务必混入 **通用数据** 防止变傻。
4.  **调试**：如果你发现模型学不会知识，加大 Rank 并确保 FFN 被训练；如果你发现模型变傻了，减小 Rank 或增加通用数据比例。

### 2.1.6 架构维度：为什么要微调 FFN？知识到底在哪？

**核心论点**：Transformer 的 Attention 负责“路由信息（关注哪里）”，而 FFN（前馈网络）负责“存储知识（是什么）”。

#### 2.1.6.1 证据 A：ROME 论文 (Locating and Editing Factual Associations in GPT)
*   **论文来源**：*Meng et al., NeurIPS 2022*
*   **实验设计**：研究人员试图找出 GPT-2 在回答“埃菲尔铁塔在哪？”（答案：巴黎）时，大脑里哪块区域亮了。他们使用了**因果追踪（Causal Tracing）**技术，通过干扰并恢复特定层的激活状态，看输出概率的恢复情况。
*   **数据表现**：
    *   实验发现，当恢复 **中层前馈网络 (MLP/FFN)** 的激活时，模型恢复正确答案的概率最高。
    *   Attention 层的恢复对事实性知识的影响较小。
*   **原文洞察**：
    > "Fact retrieval from the MLP weights can be modeled as a key-value memory lookup."
    > (从 MLP 权重中检索事实可以被建模为一个键值记忆查找过程。)
*   **结论应用**：如果你做**行业知识注入**（如医疗、法律），必须微调 FFN。如果你只微调 Attention，模型学会了“医生的语气”，但要把“头疼”关联到“阿司匹林”这一步（Key-Value 映射），是在 FFN 里完成的。

#### 2.1.6.2 证据 B：QLoRA 论文
*   **论文来源**：*Dettmers et al., NeurIPS 2023*
*   **实验设计**：对比仅微调 Attention 层 vs. 微调所有线性层（Attention + FFN）。
*   **数据表现 (MMLU 5-shot Accuracy)**：
    *   `LoRA (Attention only)`: 精度 **47.1%**
    *   `LoRA (All Linear Layers)`: 精度 **48.3%**
    *   注：在 Vicuna 基准测试中，All Linear 的表现接近 GPT-4 的 99.3%，而仅微调 Attention 只有 97. X%。
*   **结论应用**：Target All Linear Layers 是目前的标准动作，虽然参数量增加了，但性能提升是实打实的。

### 2.1.7 参数维度：Rank 的选择与本质

**核心论点**：大模型的改动具有“低本征维度（Low Intrinsic Dimension）”，即大部分参数其实不需要动，动一点点关键的投影就能改变输出。

#### 2.1.7.1 证据 C：LoRA 原始论文
*   **论文来源**：*Hu et al., ICLR 2022*
*   **实验设计**：在 GPT-3 175 B 上进行 WikiSQL 和 MultiNLI 任务微调，测试不同 Rank (r) 的效果。
*   **数据表现 (WikiSQL Accuracy)**：
    *   `r=1`: 73.4%
    *   `r=2`: 73.6%
    *   `r=4`: 73.8%
    *   `r=8`: 73.8%
    *   `r=64`: 73.5%
*   **反直觉现象**：你可以看到，从 r=4 增加到 r=64，**效果并没有提升，甚至略有下降**。
*   **原文洞察**：
    > "A low rank is sufficient... The update matrix $\Delta W$ has a very low intrinsic rank."
    > (一个低秩就足够了……更新矩阵 $\Delta W$ 具有非常低的本征秩。)
*   **子空间相似性实验**：作者对比了 r=8 和 r=64 训练出来的两个矩阵，发现它们共享了很大一部分“子空间”。这意味着 r=64 学到的多余维度主要是噪声。
*   **结论应用**：
    *   对于**格式对齐/简单任务**：r=8 足够，甚至是杀鸡用牛刀。
    *   **反转**：但在后来的**复杂逻辑/代码任务**（如 Magicoder, DeepSeek-Coder 微调）中，社区发现 **r=64 或 r=128** 更好。这是因为“逻辑重组”比“格式对齐”需要更高的本征维度，原始 LoRA 论文的任务相对简单（分类和简单生成）。

### 2.1.8 数据维度：LIMA 假设 (Less Is More for Alignment)

**核心论点**：SFT（有监督微调）的主要作用不是学习新知识，而是**激活**模型预训练时已经学会的知识和格式。

#### 2.1.8.1 证据 D：LIMA 论文
*   **论文来源**：*Zhou et al. (Meta AI), NeurIPS 2023*
*   **实验设计**：
    *   模型 A：在 50,000 条常规指令数据上微调。
    *   模型 B (LIMA)：仅在 **1,000 条** 人工精选的高质量数据上微调。
*   **数据表现**：
    *   在人类评估（Human Eval）中，LIMA 模型生成的回复质量，**击败了** 基于 50 k 数据训练的 Alpaca，甚至在 43% 的情况下优于 GPT-4。
*   **原文洞察**：
    > "Superficial Alignment Hypothesis: A model’s knowledge and capabilities are learnt almost entirely during pretraining, while alignment teaches it which sub-distribution of formats should be used."
    > (表面对齐假设：模型的知识和能力几乎完全是在预训练阶段学到的，而对齐（微调）只是教它应该使用哪种格式的子分布。)
*   **结论应用**：
    *   如果你做微调，**清洗数据的时间应该占 80%**。
    *   如果你有 10 万条从网上爬下来的脏数据，不如人工清洗出 1000 条黄金数据。
    *   这也解释了为什么微调容易发生“灾难性遗忘”——你用 1000 条特定分布的数据去强行拉扯模型，它很容易忘记原本广博的“预训练分布”。

### 2.1.9 优化维度：LoRA+ (为什么 A 和 B 不能一视同仁)

**核心论点**：在标准 LoRA 中，矩阵 A（降维）和矩阵 B（升维）的学习效率是不一样的。

#### 2.1.9.1 证据 E：LoRA+ 论文
*   **论文来源**：*Hayou et al., 2024*
*   **理论分析**：LoRA 的更新量是 $\Delta W = B A$。作者从数学上证明了，为了让训练最快收敛，矩阵 B 的学习率应该远大于矩阵 A 的学习率。
*   **原文洞察**：
    > "Standard LoRA training is suboptimal... Matrix B should have a higher learning rate to match the initialization scale."
    > (标准 LoRA 训练不是最优的……矩阵 B 应该拥有更高的学习率以匹配初始化尺度。)
*   **工程建议**：
    *   这就是为什么现在的微调框架（如 LLaMA-Factory）中会有 `lora_alpha` 这个参数。
    *   通常设置 `alpha = 2 * rank` (比如 r=16, alpha=32)。这本质上是在放大更新的权重，模拟了让 B 矩阵学得更“猛”一点的效果。
    *   **LoRA+** 更是直接建议：为 A 和 B 设置不同的 Learning Rate (ratio $\lambda \approx 10^2$)。
