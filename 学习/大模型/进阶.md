# 1 大模型微调知识储备

> 大模型微调岗面试仅仅会使用微调方法很明显是不够的，还有哪些需要加强学习的，比如说创新点之类的

你这个判断**非常到位**：
👉 **只会“怎么微调”在大模型微调岗面试里是远远不够的**，那只是“入门操作”，而不是“研究/工程能力”的体现。

我给你一个**面试官视角下的能力地图**，分成 5 大块，顺便点出**哪些地方最容易体现“创新点”**。

---

## 1.1 一、模型层面（不只是 LoRA/QLoRA 会用）

> 面试官真正关心的是：**你知不知道“为什么要这么调”**

### 1.1.1 你至少要掌握的
- **全参数微调 vs PEFT**
  - LoRA / QLoRA / AdaLoRA / IA 3
  - Prefix / P-Tuning v 2
- **不同任务该选什么微调方式**
  - 分类 / 生成 / 对话 / RAG
- **微调失效的原因**
  - 灾难性遗忘
  - Overfitting（尤其是小数据）
  - Alignment 偏移

### 1.1.2 能加分的“创新点”
- 结合任务结构设计 **LoRA 插入位置策略**
- 动态 rank / 层级 LoRA
- 多任务共享 + 任务专属 adapter

👉 面试常问：
> “你觉得 LoRA 插在 attention 还是 FFN 更合适？为什么？”

---

## 1.2 二、数据层面（这是**最容易拉开差距**的地方）

> 很多候选人**模型讲得很溜，但数据一塌糊涂**

### 1.2.1 必须会
- 数据清洗：
  - 去重、低质量样本过滤
  - 指令一致性
- 数据构造：
  - 指令数据设计（Instruction Tuning）
  - 正负样本构造
- 数据分布分析：
  - Train / val 分布偏差
  - Long-tail 问题

### 1.2.2 真正的创新点（🔥面试官爱听）
- **数据比模型更重要的论证**
- 数据 curriculum learning
- 人工规则 + LLM 生成数据混合
- 失败案例反向生成数据（error-driven data mining）

👉 面试高频问题：
> “如果数据只有 2 k 条，你怎么提升效果？”

---

## 1.3 三、训练 & 工程能力（是否“能落地”）

### 1.3.1 基本功
- 分布式训练：
  - DDP / FSDP / ZeRO
- 显存优化：
  - Gradient checkpointing
  - Mixed precision
- 训练稳定性：
  - Loss 不收敛排查
  - Nan / inf 处理

### 1.3.2 进阶加分点
- **参数效率 vs 性能权衡**
- 多卡异构训练
- 训练速度优化（通信 vs 计算）

👉 面试官判断你是“会跑实验”还是“会调系统”就在这

---

## 1.4 四、评估 & 失败分析（90% 人忽略）

> 会微调 ≠ 知道模型好不好

### 1.4.1 必须具备
- 自动指标：
  - BLEU / ROUGE / Accuracy / F 1
- 人工评估：
  - 维度设计（helpfulness / faithfulness / safety）
- A/B test 思路

### 1.4.2 高级能力（创新 + 思考）
- 针对任务的 **自定义指标**
- Bad case 分类归因：
  - 数据问题？
  - 模型能力边界？
  - 推理策略问题？

👉 面试杀手锏：
> “你如何判断模型是真的学会了，而不是记住了？”

---

## 1.5 五、对齐 & 推理阶段（很多人断层）

### 1.5.1 要会
- SFT vs RLHF vs DPO
- 解码策略：
  - Temperature / top-p / beam
- Prompt 与微调的边界

### 1.5.2 创新方向
- 微调 + prompt 协同设计
- Task-specific decoding
- 推理阶段规则约束（post-process）

---

## 1.6 面试官眼中的“创新点”是什么？

⚠️ **不是：**
- “我用了 LoRA”
- “我调了 learning rate”

✅ **而是：**
- 为什么这样设计？
- 遇到问题你怎么定位？
- 如果条件变了你怎么办？

---

## 1.7 一个“及格线 vs 优秀候选人”的对比

| 能力 | 普通候选人 | 优秀候选人 |
|----|----|----|
| 微调 | 会跑代码 | 知道为什么有效/无效 |
| 数据 | 用现成数据 | 会造、会筛、会分析 |
| 评估 | 看 loss | 有体系 |
| 创新 | 换参数 | 换思路 |
| 表达 | 描述流程 | 抽象方法论 |
