# 1 大模型架构与原理
## 1.1 旋转位置编码（RoPE）
RoPE通过**旋转token embedding**而非添加位置向量，在注意力计算中自然引入**相对位置信息**，解决了传统<span style="background:#ff4d4f">正余弦编码的局限性</span>
### 1.1.1 正余弦编码的局限
在自注意力机制中，注意力分数的计算公式是：
$$
Attention(Q, K, V) = softmax({{QK^T}\over{\sqrt{d_k}}})V
$$
其中， $Q、K、V$ 由隐藏层状态 H 经过注意力矩阵投影得到
$Q = H W^Q$ 、$K = H W^K$ 、$V = H W^V$ ， $H \in \mathcal{R}^{n \times d}$ ,  $W^Q, W^K, W^V \in \mathcal{R}^{d \times d_k}$ 
<font color="#00b050">在模型的第一层，隐藏层状态 H 通常等于 token 的 embedding；</font>
<font color="#00b050">在模型的后续层，隐藏层状态 H 由上层输出产生。</font>

**自注意力分数是并行计算的，是没有顺序的，是无法区分 “我喜欢猫” 和 “猫喜欢我”。**

为解决这个问题，需要引入<font color="#c0504d">位置编码</font>。最经典的方案是<font color="#ff0000">正余弦位置编码</font>，它给每个位置一个<font color="#9bbb59">固定向量</font>，通过不同频率的正余弦波编码绝对位置、相对位置信息。

可以看到，每个位置编码向量都是sin和cos交替.

- 局限性
	1. 不能显式建模相对位置关系
	   正余弦编码虽能反映相对位置，但其生成的相对位置信息在<font color="#ff0000">自注意力计算中被破坏</font>。自注意力机制中，位置编码会先与词向量相加，再经过线性变换，导致变换后的位置编码失去原有的相对位置特性。
	2. 灵活性与适应性不足
	   正余弦编码为固定函数生成，无法像可学习位置编码那样根据任务数据调整。
	3. 长序列外推能力有限
	   低维度（高频）编码在短距离内变化剧烈，但对长距离位置不敏感；
	   高维度（低频）编码周期长，导致长序列中不同位置的编码相似度增高，区分度下降
### 1.1.2 旋转位置编码（RoPE）
旋转位置编码RoPE是一种 `固定式` 的 `绝对位置编码` 策略，但是它的绝对位置编码配合Transformer的Attention内积注意力机制能达到 `相对位置编码` 的效果.
RoPE的<font color="#ff0000">本质</font>是对两个token形成的**Query和Key向量做一个变换**，使得变换后的Query和Key带有位置信息，进一步使得<font color="#00b050">Attention的内积操作不需要做任何更改</font>就能自动感知到相对位置信息。
换句话说，RoPR的出发点和策略用的相对位置编码思想，但是实现方式的确用的是绝对位置编码。
RoPE 没有选择<font color="#00b050">把位置向量加到 token embedding 上</font>，而是在每次计算自注意力分数时，让 Q、K 矩阵中的每个行向量根据各自的位置旋转一个角度。

我们先把 token embedding 降维到一个二维平面来直观理解，假设位置为 m 的 token 向量是 (x1, x2)。那么 RoPE 会把它绕原点旋转 **mθ** 度。
- 第 1 个 token 旋转角度 θ；
- 第 2 个 token 旋转角度 2θ；
- 第 3 个 token 旋转角度 3θ；
这样，第 m 个 token 和第 n 个 token 的**相对旋转角度**为 (m−n)θ ，也就是相对位置。
![image.png](https://learning-1316972768.cos.ap-nanjing.myqcloud.com/%E5%90%8E%E6%9C%9F/202408/20250928211823.png)

绝对位置编码表明RoPE给文本的每个位置单词都分配了一个位置表征，和三角sin-cos位置编码一样，RoPE通过t<font color="#00b050">oken在句子中的位置</font>，token embedding中<font color="#00b050">每个元素的位置</font>，这<font color="#00b050">两个要素一起</font>确定位置编码的表达，先给出RoPE的公式如下：
![image.png](https://learning-1316972768.cos.ap-nanjing.myqcloud.com/%E5%90%8E%E6%9C%9F/202408/20250928213019.png)
公式是将一个原始的token向量改造为一个注入位置信息之后的新向量的过程。  
- 第一项代表某个位置为m的token的<font color="#00b050">原始Query向量</font>，0~d-1代表向量每个位置的元素，d代表向量的维度
- 第二项为一个同样长度是d的带有cos三角函数的向量，它和Query向量逐位相乘
- 第三项由原始Query变换而来
- 第四项和第二项类似区别是将cos替换为sin
该公式的目的是将原始Query向量改造成一个带有位置信息的新向量，位置信息由参数m和θ进行表征，其中m为token在句子中的位置，θ的下标和向量中各元素的位置直接相关，公式如下：
![image.png](https://learning-1316972768.cos.ap-nanjing.myqcloud.com/%E5%90%8E%E6%9C%9F/202408/20250928213140.png)
因此只要给到某个token的输入Query向量，知道token在上下文窗口下处于第几位，就可以将它的Query向量通过RoPE的公式改造为一个新的向量形式，新形成的向量和原向量维度完全一致。以“我爱你”这句话中的第二个词“爱”为例，设词向量的维度d=4，词向量表征为[0.2, 0.1, -0.3, 0.7]，则经过RoPE变化的计算示意图如下:
![image.png](https://learning-1316972768.cos.ap-nanjing.myqcloud.com/%E5%90%8E%E6%9C%9F/202408/20250928213207.png)
公式中的第三项由原始向量变换而来，对于原始输入向量，将 `前后两个元素位置构成一对`，交换两者的位置，并且对于<font color="#00b050">偶数位取了相反数</font>
因此每个元素位的注入位置信息的过程，可以看成是该元素和它相邻的元素，分别经过sin，cos三角函数加权求和的结果
比如q0的RoPE结果是q0和q1这一对元素经过三角函数变换的结果。
在Transformer原生的三角sin-cos位置编码中，采用相加的形式将位置编码融入到词向量中，而在RoPE中采用的是类似哈达马积的乘积形式，读者可以将以上RoPE公式做的事情类比于Transformer中原始向量表征和sin-cos位置编码相加的过程。
