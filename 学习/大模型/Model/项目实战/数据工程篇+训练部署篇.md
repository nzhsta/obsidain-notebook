# 1. 大模型落地方式
大模型应用落地：
1. 微调
2. RAG

- **微调可以做什么**
  基于现有的私有数据，让模型具备处理该数据的能力
> [!attention]
> 针对基于大模型的专业问答系统，**核心技术并不是通过微调**实现，
> 专业问答系统的应用落地核心是**基于RAG实现**（微调+RAG）
> **RAG提供专业回答，而微调可以改变回复的话术（拟人化）**
- **为什么不通过微调实现专业问答系统**
	1. <font color="#ff0000">大模型存在缺陷——幻觉问题</font>
		离线大模型一本正经的胡说八道
		对于专业的问答系统，幻觉的存在是不可容忍的，而<font color="#ff0000">模型微调无法杜绝幻觉问题</font>
	2. 微调是受到训练数据约束的，<font color="#ff0000">无法动态适应</font>由于业务场景改变而带来的变化
- **微调目前如何落地**
	如果当前的业务场景涉及到<span style="background:rgba(2, 170, 11, 0.55)">模型本身</span>的改变
	1. <font color="#00b050">自我认知改变</font>（名称、功能介绍等）
	2. <font color="#00b050">模型的对话风格</font>
	3. 针对专业问答系统的问题<font color="#ff0000">理解不到位</font>时
		1. 换模型（更大参数的模型）
		2. 会使用微调技术帮助**理解用户问题**

### 3.1.2 本项目的数据情况
- 本项目的数据来源
	1. 人工指定（成本高）
	2. 基于现有开源数据，让ai实现情绪数据制作（速度快，效果无法保证）
> [!attention] AI处理的注意事项
> 如果让AI帮忙处理数据，尽可能选择效果较好的API接口，不要使用本地的大模型来处理

- **数据处理**
	1. 准备部分现有对话数据（AI生成）
	2. 数据审查
		- 是否为空？长度要求？是否符合情绪核心词标注？
	3. 数据去重（**语义相似度比较**）
		- 例子
		   q:几天心情不太好
		   a1:怎么了呀，可以给我说说吗？
		   a2:怎么了，可以给我说说吗？
		   a3:怎么了，能给我说说吗？
		- 流程
		  1. 对文本编码(embedding模型)
		  2. 比较相似度
		  3. 设定阈值

## 3.2 embedding model 验证和转换
![image.png](https://learning-1316972768.cos.ap-nanjing.myqcloud.com/%E5%AD%A6%E4%B9%A0/largeModel/20251001155638039.png)

> [!attention] 模型选择
> 
- 模型分两种
	- 以 `sentence` 结尾的模型——<span style="background:rgba(2, 170, 11, 0.55)">sentence transformer</span>格式（**推荐**）
	- 不跟 `sentence` 的模型——huggingFace transformer 格式（基本格式）
- 结构
  ```shell
  text2vec-base-chinese-sentence/ 
  ├── 0_Transformer/ 模型结构
  ├── 1_Pooling/ 一般sentence-transformer带有
  ├── 2_Normalize/ 归一化层
  ├── config.json 
  ├── config_sentence_transformers.json 
  ├── modules.json 
  └── pytorch_model.bin
  ```
	一般带有 polling 层的都是 sentence-transformer。
	Embedding_model 通常情况是<font color="#00b050">自带有归一化层</font>的。一般可以通过 Normalize 目录或者 modules. Json 来判断是否准确包含归一化层，或者判断<font color="#00b050">它的模长是否接近 1</font>。如果未包含归一化层，则需要<font color="#c00000">手动转换</font>添加。
	- 手动添加方法
		```python
		import numpy as np 
		from sentence_transformers 
		import SentenceTransformer,models 
		model_path = r"D:\PycharmProjects\demo_15\embedding_model\sungw111\text2vec- base-chinese-sentence" 
		bert = models.Transformer(model_path) 
		# 添加缺失的归一化层 
		pooling = models.Pooling(bert.get_word_embedding_dimension(), pooling_mode='mean') 
		normalize = models.Normalize()
		# 组合完整模型 
		full_model = SentenceTransformer(modules=[bert, pooling, normalize]) p
		rint(full_model) 
		save_path=r"D:\PycharmProjects\demo_15\embedding_model\zy\text2vec-base-chinese- sentence" 
		full_model.save(save_path) 
		# 加载修复后的模型 
		model = SentenceTransformer(r"D:\PycharmProjects\demo_15\embedding_model\zy\text2vec- base-chinese-sentence") 
		# 验证向量归一化 
		text = "测试文本" 
		vec = model.encode(text) 
		print("修正后模长:", np.linalg.norm(vec)) # 应输出≈1.0
		```

### 3.3.2 模型大小
<span style="background:#ff4d4f">显存计算方法</span>
- **核心指标**
	- **显存（GPU Memory）**：  
	    需容纳 **模型参数 + 激活值 + 优化器状态**。例如，训练一个1B参数的FP16模型，至少需要：
	    - 参数：2GB
	    - 激活值：~4GB（假设批次大小适中）
	    - 优化器状态（如Adam）：参数量的2倍（4GB）  
	        **总计：约10GB**（实际需预留20%缓冲，建议≥16GB显存）。
	- **计算能力（FLOPS）**：  
	    大模型训练主要依赖Tensor Core性能（如NVIDIA A100的FP16算力达312 TFLOPS）。估算所需算力：  
	    **总FLOPs ≈ 6×参数量×训练数据量**（6来自前向+反向传播的乘加操作）。  
	    例如，1B参数模型训练10B tokens需要约 **6×10¹⁹ FLOPs**，A100约需 **2天**（理论值，实际受内存带宽限制）。
	    
	- **内存带宽（Memory Bandwidth）**：  
	    影响数据加载速度。如A100的显存带宽为 **2TB/s**，若批次过大导致频繁换入换出，会成为瓶颈。
- **显存占用估算**：  
    使用 **[Hugging Face Model Memory Calculator](https://huggingface.co/spaces/hf-accelerate/model-memory-usage)** 或以下公式：  
    **总显存（GB） ≈ 参数量（B）× 精度字节数 （FP16）× 4**（4倍参数量的经验值，含激活和优化器）。
- **训练时间估算**：  
    **时间（小时） = 总FLOPs ÷ GPU算力（TFLOPS） ÷ 3600 ÷ 利用率**（利用率通常按30%~50%计算）。

1. 服务器配置
   根据配置，顶到最高
2. 任务的复杂度
