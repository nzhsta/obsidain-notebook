# 2 Distilling the Knowledge in a Neural Network
**神经网络中的知识蒸馏**

> **原文标题：** Distilling the Knowledge in a Neural Network
> **作者：** Geoffrey Hinton, Oriol Vinyals, Jeff Dean (Google)
> **发表时间：** NIPS 2015 Deep Learning Workshop
> **文档整理与批注：** Antigravity AI
> **适用人群：** 从 SFT 转入模型优化的算法工程师

---

## 2.1 核心摘要 (Abstract)

提高机器学习算法性能的一个非常简单且有效的方法是：在同一份数据上训练许多不同的模型，然后在测试时对它们的预测结果取平均（即**集成学习 Ensemble**）。

然而，这种集成模型通常非常**笨重 (Cumbersome)**，计算成本过高，难以部署给大量用户使用。

本文证明了，我们可以将集成模型（或一个巨大的模型）中的知识，压缩到一个单一的**小模型 (Small Model)** 中。我们将这种方法称为“**蒸馏**” (Distillation)。

我们在 MNIST（手写数字）任务上取得了令人惊讶的结果，并且表明我们可以通过引入一种新的“**软目标**” (Soft Targets) 训练方法，显著改善声学模型（ASR）的表现。

> **【SFT 开发者视角】**
> *   **原来的困境：** 想用 Llama-3-70B 给用户提供服务，但推理成本太高，速度太慢。
> *   **本文的方案：** 用 70B 模型当老师，教 8B 模型（学生）。如果教得好，8B 模型的效果能接近 70B，但速度快 10 倍。

---

## 2.2 引言 (Introduction)

### 2.2.1 昆虫的启示：训练与部署的分离
许多昆虫都有两个截然不同的形态：
1.  **幼虫形态 (Larval form)：** 专注于从环境中汲取营养，主要目标是长身体（对应**训练阶段**）。
2.  **成虫形态 (Adult form)：** 专注于迁徙和繁殖，要求身体轻便、行动敏捷（对应**部署阶段**）。

在大规模机器学习中，我们也应该遵循这个逻辑：
*   **训练阶段：** 我们可以使用非常复杂的模型（如万亿参数的 MoE，或者多个模型的集成），目的是从数据中提取尽可能多的结构和知识。只要能提取出来，模型多慢都无所谓。
*   **部署阶段：** 我们需要一个轻量级的模型，能满足低延迟、低能耗的要求。

### 2.2.2 暗知识 (Dark Knowledge) 与软目标 (Soft Targets)
通常，我们训练模型的目标是最大化正确类别的概率（即拟合 **Hard Label**）。
例如：一张图片是“宝马汽车”。
*   **Hard Label (SFT):** `[0, 0, 1, 0, ...]` （只有宝马是1，其他全0）。
*   **Teacher Model Output:** `[0.001, 0.05, 0.9, 0.04, ...]`

在 Teacher 的输出中，虽然“宝马”概率最高（0.9），但它给“垃圾车”的概率（例如 $10^{-9}$）和给“胡萝卜”的概率（例如 $10^{-100}$）是不同的。
更重要的是，它可能给“奥迪汽车”分配了 `0.05` 的概率。

**这个 `0.05` 非常关键！**
它告诉了我们：这张图虽然是宝马，但它长得有点像奥迪。这种**类与类之间的相似性结构 (Structure of similarity)**，就是大模型学到的“暗知识”。
*   如果只用 Hard Label 训练，这部分信息就丢了。
*   蒸馏的目的，就是让小模型学会这个 `0.05`。

## 2.3 蒸馏方法 (Distillation) - **【核心数学原理】**

### 2.3.1 温度 (Temperature)
神经网络的输出层通常使用 Softmax 将 Logits ($z_i$) 转换为概率 ($q_i$)。为了显露“暗知识”，我们引入温度 $T$：

$$ q_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)} $$

*   **$T=1$：** 标准 Softmax。
*   **$T > 1$：** 概率分布变平滑（Soft）。
    *   例如：`[0.01, 0.99]` 在高温下可能变成 `[0.4, 0.6]`。
    *   **作用：** 高温放大了原本很小的概率值（如上面的“奥迪”概率），让学生模型能更清楚地学习到这些细微的知识。

### 2.3.2 损失函数 (Loss Function)
我们在训练学生模型时，通过最小化两个 Loss 的加权和来进行：

1.  **$L_{soft}$ (蒸馏损失):**
    *   让 Teacher 和 Student 都以**高温 $T$** 输出概率。
    *   计算两者之间的 **KL 散度 (Kullback-Leibler Divergence)** 或<font color="#c00000">交叉熵</font>。
        * $$D_{KL}​(PT^T​∣∣PT^S​)=∑_{i}​P_{T,i}^T​⋅log\left( \frac{P^T_{T,i}}{P^S_{T,i}} \right)$$
        *  $$D_{KL}​=∑P_{T}^T\log P_{T}^T​​​-∑P_{T}^T\log P_{T}^S = 老师的熵（常数）-老师和学生的交叉熵$$
        * 注意第一项（老师的熵）：因为老师的模型是冻结的，它的输出分布是固定的，所以这一项对于梯度下降来说是**常数 (Constant)**，求导为 0。
		- 因此，**最小化 KL 散度，等价于最小化老师和学生的交叉熵。**
	    *   *目的：* 学习老师的思维方式和暗知识——<span style="background:#ff4d4f">高温T</span>。

2.  **$L_{hard}$ (学生本身的 SFT 损失):**
    *   让 Student 以 **$T=1$** 输出概率。
    *   计算其与 **真实标签 (Ground Truth)** 的<font color="#c00000">交叉熵</font>。
    *   *目的：* 保证学生别学歪了，最终还是要答对标准答案。

$$ L_{total} = \alpha T^2 \cdot L_{soft}(P_T^S, P_T^T) + (1-\alpha) \cdot L_{hard}(P_1^S, y_{true}) $$

> **【注：关于 $T^2$ 的缩放】**
> 论文中提到，如果使用 $L_{soft}$ 的梯度推导，梯度的大小会随着 $T^2$ 缩小（大致为 $1/T^2$）。
> 为了让 $L_{soft}$ 和 $L_{hard}$ 的梯度处于同一个数量级，我们在代码实现时，通常需要手动给 $L_{soft}$ 乘以 $T^2$。
> **代码避坑指南：** PyTorch 的 `kl_div` 默认不带这个系数，你需要自己乘！

| Temperature | 适用场景    | 效果     | 推荐度     |
| ----------- | ------- | ------ | ------- |
| **T=1**     | 推理阶段    | 保持原始分布 | 推理✅ 训练❌ |
| **T=2-4**   | 图像分类蒸馏  | 适度软化   | 分类任务✅   |
| **T=5-10**  | NLP任务蒸馏 | 明显软化   | LLM蒸馏✅  |
| **T=20+**   | 高度混淆任务  | 极度软化   | 特殊情况⚠️  |

### 2.3.3 匹配 Logits (Matching Logits) 的特例
论文推导了一个有趣的结论：


当 $T \to \infty$ （温度趋近于无穷大）时，蒸馏 Loss 本质上等价于最小化 Logits 之间的均方误差（Mean Squared Error）：
$$ \frac{1}{2}(z_i - v_i)^2 $$
这为后来的很多研究（如 TinyBERT）直接拟合 Hidden States 或 Logits 提供了理论依据。

## 2.4 实验验证：MNIST (Preliminary Experiments)

作者在 MNIST 手写数据集上做了一个非常有趣的实验，证明了蒸馏不仅仅是模仿，而是**泛化能力的迁移**。

*   **Teacher:** 一个包含 1200 个神经元的大网络，使用了 Dropout。
*   **Student:** 一个包含 800 个神经元的小网络。

### 2.4.1 关键实验：消失的数字 "3"
作者在训练 Student 时，故意从训练数据中**移除了所有数字 "3"**。
这意味着 Student 从未见过任何一张真实的 "3" 的图片。
但是，Teacher 见过 "3"。

**结果：**
经过蒸馏训练后，Student 在测试集上识别 "3" 的准确率并没有崩盘，虽然比不上正常训练，但依然能识别大部分的 "3"。

**原因解析：**
当 Teacher 看到一张 "3" 的图片时，虽然 Student 没见过这张图，但 Teacher 可能会输出：
> "这是 3 的概率是 0.9，这是 8 的概率是 0.09"
或者当 Teacher 看到 "8" 时输出：
> "这是 8 的概率是 0.9，这是 3 的概率是 0.05"

Student 通过学习 Teacher 对 "8" 的描述（它长得有点像 3），间接学会了 "3" 的特征（比如圆弧结构）。

> **【SFT 开发者视角】**
> 这个实验解释了为什么大模型蒸馏能提升小模型的**泛化性 (Generalization)**。
> 即使你的 SFT 数据集覆盖不全，只要 Teacher 足够强，它就能通过 Soft Label 把“未见过的场景逻辑”传授给小模型。

## 2.5 实验验证：语音识别 (Speech Recognition)

作者在工业级的语音识别任务上进行了测试。
*   **基线 (Baseline):** 单个模型，帧准确率 58.9%。
*   **集成模型 (10x Ensemble):** 帧准确率 61.1%。
*   **蒸馏后的单模型 (Distilled):** 帧准确率 **60.8%**。

**结论：**
蒸馏后的小模型，效果几乎追平了 10 个模型的集成，但推理算力只有原来的 1/10 甚至更少。这直接确立了 KD 在工业界落地的地位。

## 2.6 附录：从论文到 LLM 实战 (From Paper to Code)

作为开发者，在将这篇 2015 年的论文应用于 LLM 时，需要注意以下几点 **Critical Changes**：

### 2.6.1 词表对齐问题 (The Tokenizer Mismatch)
Hinton 的论文假设 Teacher 和 Student 的输出层维度一致（都是 0-9 或者 2000 个）。
但在 LLM 中：
*   Teacher (e.g., GPT-4): 词表未知或不同。
*   Student (e.g., Llama-3): 词表 128k。

**解决方案：**
1.  **同源蒸馏：** 尽量选架构相同的模型（如 Qwen2.5-72B 蒸馏给 Qwen2.5-7B），这样 Tokenizer 完全一致，可以直接照搬论文公式。
2.  **黑盒蒸馏 (Sequence KD):** 如果词表不同，放弃 Logits 蒸馏，直接把 Teacher 生成的文本作为 Student 的 Hard Label 进行训练（相当于 $T \to 0$ 的极端情况）。

### 2.6.2 序列生成问题 (Sequence Generation)
论文处理的是分类问题（输入一张图 -> 输出一个概率分布）。
LLM 是序列生成（输入 Prompt -> 输出 Token 1 -> 输出 Token 2...）。

在 LLM 蒸馏中，Loss 是在每一个 Token 位置上计算的平均值：
$$ L_{KD} = \frac{1}{N} \sum_{t=1}^{N} KL(P_{Teacher}(\cdot|x, y_{<t}), P_{Student}(\cdot|x, y_{<t})) $$

### 2.6.3 推荐的 PyTorch 代码实现逻辑

```python
import torch.nn.functional as F

def compute_distillation_loss(student_logits, teacher_logits, labels, T=2.0, alpha=0.5):
    """
    参数:
    student_logits: [batch_size, seq_len, vocab_size]
    teacher_logits: [batch_size, seq_len, vocab_size] (需与 student 对齐)
    labels: 真实标签
    T: 温度
    alpha: 软硬 Loss 的权重平衡 (0.5 表示各占一半)
    """
    
    # 1. Hard Label Loss (常规 SFT Loss)
    # 只需要计算 student 和 ground truth 的差异
    loss_ce = F.cross_entropy(
        student_logits.view(-1, student_logits.size(-1)), 
        labels.view(-1)
    )
    
    # 2. Soft Label Loss (知识蒸馏 Loss)
    # 关键步骤：先除以 T，再做 softmax/log_softmax
    student_log_probs = F.log_softmax(student_logits / T, dim=-1)
    teacher_probs = F.softmax(teacher_logits / T, dim=-1)
    
    # 计算 KL 散度
    # reduction='batchmean' 是 PyTorch 推荐的 KL 计算方式
    loss_kl = F.kl_div(student_log_probs, teacher_probs, reduction='batchmean')
    
    # 3. 核心修正：乘以 T^2
    # 如论文所述，为了保持梯度量级，必须乘以 T^2
    loss_kl = loss_kl * (T ** 2)
    
    # 4. 总 Loss
    total_loss = alpha * loss_ce + (1 - alpha) * loss_kl
    
    return total_loss
```

## 3.1 一句话抓住论文（TL;DR）

作者提出 **Distilling step-by-step（逐步蒸馏）**：
	先用大模型（LLM）对训练样本生成 **“标签 + 推理解释（rationale/CoT）”**
	再把小模型训练成一个**多任务**模型：既学“预测标签”，也学“生成解释”。
	这样小模型在**更少训练数据**、**更小参数规模**下，能在多个任务上**追平甚至超过**大模型 few-shot CoT 的效果。turn12view2turn13view1turn13view3

---

## 3.2 论文要解决的问题与动机

### 3.2.1 为什么不直接上 LLM？

LLM（例如 175B 量级）部署成本高：论文引用的例子是，服务一个 175B 模型可能需要至少 **350GB GPU 显存**（还要专用基础设施），而且当时 SOTA LLM 已经超过 **500B** 参数，进一步加剧部署压力。

> 🛠️ **注释**：
> 
> 	这句话的“重点”不是 350GB 的精确数值，而是：**推理端成本/延迟/显存**会逼迫很多团队走“小模型专用化”。
>     
> 	现实里你也常遇到：LLM 很强，但 **SLA（延迟/吞吐）** 或 **成本** 不允许全量调用。
>     

### 3.2.2 传统小模型训练的两条路都“吃数据”

小模型通常：

- **标准微调（finetuning）**：用人工标注的训练集对小模型做监督学习；
    
- **标准蒸馏（distillation）**：用 LLM 给大量无标注样本打“<font color="#c00000">伪标签</font>”训练小模型。
    

但问题是：要想追上 LLM，往往得用 **大量标注数据或大量无标注数据**，数据成本也很高。

---

## 3.3 核心思想：把 LLM 当成“会推理的老师”，蒸馏的不止是标签

🚀论文的关键转变：

> 以前把 LLM 当“出伪标签的工具”；现在把 LLM 当“**能解释为什么**”**的推理者**。

LLM 给出的 **rationale（自然语言推理解释）**里往往包含任务知识（例如数学题里“面积=长×宽”这种中间规律），这能让小模型用更少样本学到更“结构化”的映射。

> 🛠️ **注释**： 可以把 rationale 当作一种“<span style="background:#40a9ff">高密度监督信号</span>”：
> 	只有标签：每条样本只给 1 个 bit/几个 token 的监督；
> 	
> 	有 rationale：监督信号变成几十到几百 token，包含“路径/规则/证据”。 这本质上在提高“每条数据的有效信息量”。
>     

---

## 3.4 方法详解（按论文 Section 3）

论文框架非常“工程友好”，就两步：

### 3.4.1 Step 1：用 few-shot CoT 从 LLM 抽取 rationales
给定训练输入样本 $x_i$，作者用 **few-shot Chain-of-Thought prompting** 构造提示模板 $p$。模板里包含若干个<font color="#00b050">三元组示例</font>：
其中 $r_p$ 是用户提供的“示例解释”，$y_p$ 是示例标签。把新样本 $x_i$ 接到提示后，让 LLM 生成：
- 解释 $\hat{r}_i$
- 标签 $\hat{y}_i$ 
    

> 🛠️ **注释（Prompt 怎么写更稳）**：
> 
> **固定输出格式**很关键：让老师始终按“Rationale: … / Label: …”之类输出，后处理会简单很多。
> 
> 示例（shots）数量：论文里提到大概 **~10-shot**。
>     
> 若你担心人工写 rationale 成本：论文也提到可用 **0-shot 方式诱导 rationale**（参考 Kojima et al., 2022 的方向）。
>     

---

### 3.4.2 Step 2：用 rationales 训练小模型（关键：多任务，而不是把 rationale 当输入）

#### 3.4.2.1 实现方式
- 标准微调 / 标准蒸馏（baseline）
	无论是用真标签 $y_i$ 还是 LLM 伪标签 $\hat{y}_i$，标准训练就是最小化标签预测的交叉熵：
	（论文里用 $\hat{y}_i$ 统指“真标签或伪标签”）
	$$\mathcal{L}_{label} = \frac{1}{N}\sum_{i=1}^N \ell(f(x_i), \hat{y}_i)$$
- 一个“看起来合理但部署不友好”的做法：把 rationale 当输入
    有些工作把 rationale 拼到输入里，训练 $f(x_i,\hat{r}_i)\rightarrow \hat{y}_i$：
    但这会导致**部署时仍需要 LLM 先生成 rationale**，违背“小模型独立部署”的目标。
    $$\mathcal{L}=\frac{1}{N}\sum_{i=1}^N \ell(f(x_i,\hat{r}_i), \hat{y}_i)$$
- 论文方法：把“生成 rationale”当成第二个任务（multi-task）
    作者把学习过程改成多任务：同一个输入 $x_i$ 下，小模型既学输出标签，也学输出 rationale：
    $$\mathcal{L} = \mathcal{L}_{label} + \lambda \mathcal{L}_{rationale}$$
    其中:$$\mathcal{L}_{rationale}=\frac{1}{N}\sum_{i=1}^N \ell(f(x_i), \hat{r}_i)$$
    关键收益：**推理时不需要 rationale 输入，也不需要 LLM**；你可以只让模型预测标签。
    
- 工程落地方式：task prefixes（**任务前缀**）
    论文用“任务前缀”把多任务落到一个 T5 模型里：对同一个 $x_i$，构造两种训练样本：
	- `"[label] " + x_i -> y`
	- `"[rationale] " + x_i -> r` 
	    

> 🛠️ **注释（这一步就是精髓）**：
> 
> - 这跟“指令微调（instruction tuning）”的精神很像：**同一个模型通过前缀切换任务**。
>     
> - 训练时你可以让模型学会“会解释”，但部署时只调用 `[label]` 这条路径，避免额外计算。
>

- 若原数据没有验证集，作者会从训练集随机抽 **10%** 当验证集；
- CQA 因原测试集标签不可用，用原 validation 当 test。
  
### 3.5.3 Baselines（对照组）

- **Standard finetuning**（有真标签）
- **Standard task distillation**（只有无标注，用 LLM 伪标签）
- **Few-shot CoT（LLM 推理时直接 prompt）**
- **PINTO tuning**（论文扩展了 PINTO 以覆盖更多任务；属于“为 LLM 加参数/适配”的思路）
    

### 3.5.4 训练超参（Appendix A.1）

- 训练在 cloud A100×16 上
- T5-Base / Large：lr=5e-5，batch=64，max_len=1024，最多 10000 steps
- T5-XXL：lr=5e-5，batch=32，max_len=1024，最多 4000 steps
- 结果报告为 4 次随机种子运行的均值，并在图里给标准误差。

## 3.6 结果与结论（论文三条主结论 + 关键数字）

### 3.6.1 结论一：同等/更好效果所需训练数据显著更少（**数据效率**）


在 **有标注**（standard finetuning 对比——**标准微调**）下，用 220M T5：
- e-SNLI：只用 **12.5%** 数据就能超过“用 100% 数据的标准微调”
- 为了超过 standard finetuning，训练样本需求减少：
    - ANLI：**减少 75%**
    - CQA：**减少 25%**
    - SVAMP：**减少 20%**
        

在 **无标注**（standard distillation 对比）下：
	Standard task distillation（标准任务蒸馏）: 先让 teacher LLM 预测一个**伪标签** $\hat{y}_i​$，再训练学生模型学它：`x_i -> y_hat_i`, **标准蒸馏只把** teacher 当“**打标机**”
- e-SNLI：只用 **12.5%** 的无标注样本，就能超过“用 100% 无标注样本做标准蒸馏”的效果 
- 图注里也提到例如 ANLI 用 12.5% 子集等趋势。
    

> 🛠️ **注释（为什么会更省数据）**： 直觉上是“监督更稠密”：rationale 让模型更快学到“可迁移的中间规律”，减少靠大量样本‘硬拟合’的需求。

---

### 3.6.2 结论二：用更小模型超过 few-shot LLM（部署效率）

在 **有标注**设置下，Distilling step-by-step 可以用更小 T5 超过 PaLM 540B 的 few-shot CoT，并且也超过 PINTO tuning：
- e-SNLI：**220M T5**（约 **2000×** 更小）
- ANLI、SVAMP：**770M T5**（约 **700×** 更小）
- CQA：**11B T5**（约 **45×** 更小）turn9view3turn10view1
    

在 **只有无标注**时：Distilling step-by-step 在 4 个数据集中的 **3/4** 上也能超过 teacher 的 few-shot CoT；在 SVAMP 上差一些，作者认为和训练集只有 ~800 规模有关。

---

### 3.6.3 结论三：同时把“模型更小 + 数据更少”做到极致（最小资源搜索）

作者以 LLM few-shot CoT 的效果为“锚点”，做了粗粒度搜索，观察达到“超过 LLM”的最低资源：
- e-SNLI：**220M T5** + **0.1%** 数据就能超过 LLM 
- ANLI：**770M** + **80%** 数据超过 LLM；而标准微调即使用 100% 数据也很难追上 
- 无标注时：例如 ANLI 用 **45× 更小模型** + **50%** 无标注集超过 LLM。
    

---

### 3.6.4 SVAMP 的额外实验：用无标注数据增强（ASDiv）

SVAMP 本身训练集很小，作者加入同类数学题数据集 ASDiv（**2,305** 条）做无标注增强。turn16view1
结果：增强能提升两种方法，但 **Distilling step-by-step 更能“吃满”新增数据的收益**，最终能用小模型把效果拉到和 few-shot CoT 接近；而 standard distillation 仍落后。turn14view0

> 🛠️ **注释（很实用的一点）**： 如果你在真实项目里遇到“标注少、同域无标注多”，这篇论文给了一个可操作策略： 1) 从无标注里让 teacher 产出“解释+标签”； 2) 让 student 同时学“解释任务”，从而更高效吸收新增样本。

## 3.7 消融实验（Section 4.4）：哪些设计真的重要？
### 3.7.1 Teacher 越强，rationale 质量越好，收益越大（但小 teacher 也有效）
![image.png](http://10.32.0.8:1998/picture/20260126195322581.png)


Table 1 对比用不同 LLM 生成 rationales：
- 标准微调（无 rationale）：e-SNLI 88.38 / ANLI 43.58 / CQA 62.19 / SVAMP 62.63
- 用 **20B GPT-NeoX** rationales：提升到 89.12 / 48.15 / 63.25 / 63.00
- 用 **540B PaLM** rationales：进一步到 89.51 / 49.58 / 63.29 / 65.50
    

> 🛠️ **注释**：
> 
> - 这意味着你不一定要 PaLM 级别 teacher 才能开始做；**但 teacher 越强，rationale 越可信，增益更大**。
>     
> - 真实项目里常用做法：先用可用的 teacher（比如企业内部大模型/较大开源模型）跑通 pipeline，再逐步换更强 teacher。
>     

### 3.7.2 为什么一定要“多任务”，而不是把 rationale+label 拼成一个输出？

Table 2 对比两种训练范式：
![image.png](http://10.32.0.8:1998/picture/20260126195236295.png)

- **Single-task**：把 `[rationale, label]` 拼成一个序列让模型一次性生成（有时甚至比标准微调更差）
- **Multi-task（论文方案）**：用前缀区分 label/rationale 两个任务，效果最好

## 3.8 局限性与伦理（论文原文要点 + 工程解读）

### 3.8.1 局限性（Limitations）

论文明确提到： 
1) 需要用户写少量示例（约 10-shot）来做 few-shot CoT 提示；未来可用无需示例的 elicitation 方法缓解；
2) 训练时多学一个 rationale 任务会带来**轻微训练开销**，但推理时可以只预测 label 避免开销； 
3) LLM 在更复杂推理/规划任务上可能推理能力有限，未来应研究 rationale 质量如何影响该方法。

### 3.8.2 伦理（Ethics）

小模型可能继承 teacher 的偏见；作者认为减少大模型反社会行为的研究进展也能迁移到小模型。

> 🛠️ **注释（实际风险）**：
> 
> - **rationale 会“放大”错误**：如果 teacher 的解释看似合理但其实错了，student 可能被“强监督”带偏。
>     
> - 建议做：rationale 过滤 / 多次采样自一致性 / 规则校验（尤其在数学、逻辑任务）。
>     
> - 如果你的数据含敏感信息：把数据发给外部 LLM 生成 rationales 可能不合规，需要内部 teacher 或脱敏策略。
>

## 3.9 工程实践：如何在你自己的任务上复刻 Distilling step-by-step？

下面给一套“从 0 到 1”的落地流程（不依赖 PaLM），重点是数据格式与训练方式。

### 3.9.1 数据管线（离线 teacher 生成）

1) 准备训练输入集合 $x_i$（可有标注，也可无标注）。 
2) 写 prompt 模板（固定格式）：
	-  N-shot 示例：每个示例包含 Input / Rationale / Label
	-  对新样本：让 teacher 输出 Rationale + Label 
3) 解析 teacher 输出，得到 $(x_i,\hat{r}_i,\hat{y}_i)$。


> 🛠️ 小技巧：
> 
> - 让 teacher 输出 JSON（或严格分隔符）能显著降低后处理成本。
>     
> - 对分类任务，建议把 label 规范化成固定词表（如 `entailment/neutral/contradiction`），避免 student 学到不稳定表述。
>     

### 3.9.2 训练样本构造（论文的 task-prefix 多任务）

对每条原始样本构造两条训练记录：

Input:  [label] <x_i>  
Target: <y_i or y_hat_i>  
​  
Input:  [rationale] <x_i>  
Target: <r_hat_i>

训练时把两类样本混在一起（或分 batch 采样），做 seq2seq 交叉熵即可。

### 3.9.3 Loss 权重怎么设？
$$Loss=α⋅L_{label}​+(1−α)⋅L_{rationale​}$$
论文公式用 $\lambda$，代码实现用 `alpha`（label loss 的权重），推荐 `alpha = 0.5`：
并给了命令行示例。

> 🛠️ 经验建议：
> 
> - 如果更关心最终任务指标（label），可以把 `alpha` 稍微调大（如 0.7）。
>     
> - 如果发现模型“学不会解释”，但解释对性能提升明显，可把 `alpha` 调小（如 0.3），先把“会想”学扎实。
>     

### 3.9.4 参考实现（来自官方仓库）
仓库地址：[GitHub - google-research/distilling-step-by-step](https://github.com/google-research/distilling-step-by-step)

仓库给了环境与运行参数示例（T5 v1.1、transformers v4.24.0 等），以及四种训练模式：标准微调、逐步蒸馏（GT label + LLM rationale）、标准蒸馏、逐步蒸馏（LLM label + LLM rationale）。

```python

python run.py --from_pretrained google/t5-v1_1-base --dataset cqa \  
  --model_type standard --label_type gt --batch_size 64  
​  
# Distilling step-by-step：GT label + LLM rationale  
python run.py --from_pretrained google/t5-v1_1-base --dataset cqa \  
  --model_type task_prefix --label_type gt --llm palm --alpha 0.5 --batch_size 64  
​  
# 标准蒸馏（LLM label）  
python run.py --from_pretrained google/t5-v1_1-base --dataset cqa \  
  --model_type standard --label_type llm --batch_size 64  
​  
# Distilling step-by-step：LLM label + LLM rationale  
python run.py --from_pretrained google/t5-v1_1-base --dataset cqa \  
  --model_type task_prefix --label_type llm --llm palm --alpha 0.5 --batch_size 64
```

> 🛠️ 工程替换建议：
> 
> - 不一定要 `--llm palm`：可以改成你能调用的 teacher（开源大模型、商业 API、内部大模型）。
>     
> - 关键是能得到 $\hat{r}_i$ 和 $\hat{y}_i$ 并按前缀多任务训练。

## 3.10 论文用到自己的项目里（实战清单）

### 3.10.1 适用场景（优先试）

- 推理链明显的任务：数学题、规则推断、NLI、需要解释的 QA/判别任务
- 标注数据贵、但你能获得无标注数据（或弱标注数据）
- 推理端成本敏感：希望“离线用大模型、线上跑小模型”
    

### 3.10.2 不适用/需要谨慎

- teacher rationale 质量差（胡编/跑题）
- 任务本身很难用自然语言解释（或解释与 label 无强相关）
- 数据有强隐私/合规限制且无法安全调用 teacher
    

### 3.10.3 上线前建议做的 3 个检查

1) **rationale-一致性检查**：解释是否支持标签？（抽样人工审 + 规则/LLM 复核） 
2) **student 鲁棒性**：只用 `[label]` 推理时是否稳定？（温度=0 的 greedy + 规范化输出） 
3) **成本核算**：teacher 离线生成的 token 成本 vs 节省的标注/推理成本
