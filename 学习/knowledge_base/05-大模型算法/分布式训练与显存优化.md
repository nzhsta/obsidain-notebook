# 分布式训练与显存优化

## 大模型显存占用计算

> 来源：2026-04-18 对话归档

**问题/场景：**
大模型训练/推理时，单卡/单节点显存往往不足以容纳模型，需要精确计算显存消耗以规划硬件配置和优化策略。

### 一、显存占用的完整来源

```
总显存 = 模型权重 + 梯度 + 优化器状态 + 激活值 + KV Cache + 临时缓冲区
```

| 组件 | 训练 | 推理 |
|-----|------|------|
| 模型权重 | ✅ FP16/BF16 | ✅ FP16/BF16/INT8/INT4 |
| 梯度 | ✅ FP32 或 FP16 | ❌ |
| 优化器状态 | ✅ Adam states (FP32) | ❌ |
| 激活值 | ✅ 中间计算结果 | ✅（可选缓存） |
| KV Cache | ❌ | ✅ 生成时逐步累积 |
| 临时缓冲区 | ✅ | ✅ |

### 二、模型权重计算

#### 2.1 精度格式对照

| 数据类型 | 后缀 | 字节数 | 用途 |
|---------|------|--------|------|
| Float32 | FP32 | 4 | 基准精度、梯度、优化器 |
| Float16 | FP16 | 2 | 混合精度训练、推理 |
| BF16 | BF16 | 2 | 混合精度训练（比FP16好） |
| INT8 | INT8 | 1 | 量化推理 |
| INT4 | INT4 | 0.5 | 量化推理 |

#### 2.2 权重计算公式

```
权重显存 = 参数量 × 每个参数的字节数
```

#### 2.3 参数量估算（Transformer）

```
总参数量 ≈ layers × (4×hidden_dim² + 2×hidden_dim²×inter_ratio) + vocab_size×hidden_dim + O(hidden_dim)

分解：
- Attention Q/K/V/O：4 × hidden_dim² × 3 + hidden_dim² × 1 = 4 × 67M × 3 + 67M = 671M
- FFN：2 × hidden_dim × inter_ratio × hidden_dim = 2 × 4 × 67M = 536M
- LayerNorm：约 0.016M × 2 = 0.032M
```

### 三、训练显存计算

#### 3.1 梯度（Gradients）

```
梯度显存 = 参数量 × 梯度精度字节数
混合精度训练：梯度用 FP16（2 bytes）
纯 FP32 训练：梯度用 FP32（4 bytes）
```

#### 3.2 优化器状态（Optimizer States）

AdamW 优化器为每个参数维护两个 FP32 状态（一阶动量 + 二阶动量）：

```
优化器显存 = 参数量 × 8 bytes（AdamW 两个 FP32 = 2 × 4 bytes）
```

#### 3.3 激活值（Activations）— 最占显存的部分

```
激活显存 ≈ batch_size × seq_len × hidden_dim × num_layers × 12 bytes（粗估）

更精确：
- 每层attention后的激活：batch × seq × hidden_dim
- 每层FFN后的激活：batch × seq × hidden_dim × inter_ratio
- Dropout mask（训练时）：batch × seq × hidden_dim
```

#### 3.4 训练显存完整公式

```
总训练显存 ≈ 权重(FP16) + 梯度(FP16) + 优化器(FP32) + 激活值

混合精度训练：
T(GB) = P × 2 + P × 2 + P × 8 + A ≈ P × 12 + A

实际经验公式（batch=1, seq=2048）：
训练显存(GB) ≈ 参数量(B) × 16
```

### 四、推理显存计算

#### 4.1 KV Cache 详细计算

每个 Transformer 层需要缓存每个 token 的 Key 和 Value 向量：

```
KV Cache（单层）= 2 × batch × seq_len × num_kv_heads × head_dim × bytes_per_param

全员 Attention 简化：
KV Cache（单层）= batch × seq_len × hidden_dim × 2 × bytes_per_param

（2 表示 K 和 V 各一份）
```

#### 4.2 推理显存估算

```
推理显存(FP16) ≈ 权重 + KV Cache + 中间激活

示例：
- 7B FP16：14 GB + 2-4 GB（KV Cache）≈ 16-18 GB
- 7B INT8：7 GB + 1-2 GB ≈ 8-9 GB
- 7B INT4：3.5 GB + 0.5-1 GB ≈ 4-5 GB
```

### 五、量化影响

| 量化方式 | 精度 | 显存压缩比 |
|---------|------|----------|
| FP16 → INT8 | 8-bit | 2x |
| FP16 → INT4 | 4-bit | 4x |
| GPTQ/AWQ | INT4+ | 4-8x（精度损失小）|

### 六、常用优化技术及显存节省

| 技术 | 显存节省 | 精度/速度影响 |
|-----|---------|-------------|
| 混合精度训练 (FP16/BF16) | 权重减半 | 几乎无损失 |
| 梯度检查点 (Gradient Checkpointing) | 激活减少 50-70% | 计算时间增加 20-30% |
| 张量并行 (Tensor Parallelism) | 分片权重/激活 | 通信开销 |
| MQA / GQA | KV Cache 减少 4-8x | 几乎无损失 |
| Flash Attention | 减少 KV Cache 中间激活 | 速度提升 |

### 七、快速计算工具函数

```python
def estimate_training_vram(params_B, batch_size=1, seq_len=2048,
                           hidden_dim=4096, num_layers=32,
                           use_gradient_checkpointing=False):
    """估算训练显存（GB）"""
    P = params_B * 1e9

    weight = P * 2 / 1e9          # FP16
    grad = P * 2 / 1e9            # FP16
    optimizer = P * 8 / 1e9       # AdamW FP32
    activation = (batch_size * seq_len * hidden_dim * num_layers * 12 / 1e9)
    if use_gradient_checkpointing:
        activation *= 0.3  # 节省约 70%

    return weight + grad + optimizer + activation

def estimate_inference_vram(params_B, batch_size=1, seq_len=2048,
                            hidden_dim=4096, num_layers=32,
                            precision="fp16"):
    """估算推理显存（GB）"""
    P = params_B * 1e9
    precision_bytes = {"fp16": 2, "int8": 1, "int4": 0.5, "bf16": 2}
    bytes_per_param = precision_bytes.get(precision, 2)

    weight = P * bytes_per_param / 1e9
    kv_cache = batch_size * seq_len * hidden_dim * num_layers * 2 * bytes_per_param / 1e9

    return weight + kv_cache
```

### 八、总结

```
训练：看 12 × 参数 + 激活（受 batch/seq 影响）
推理：看 权重 + 2-4 × batch×seq×layers×hidden（KV Cache）
```

核心规律：
- **训练显存** ≈ 参数量 × 12-16 GB（粗估，含激活）
- **推理显存** ≈ 参数量 × 2-4 GB（FP16，含 KV Cache）
- **量化到 INT8** 减半，**INT4** 再减半

## DeepSpeed ZeRO 优化

> 来源：2026-04-18 对话归档

**问题/场景：**
单卡显存无法容纳大模型的完整训练状态（参数、梯度、优化器状态），需要分布式优化方案。

**核心知识点：**
ZeRO（Zero Redundancy Optimizer）的核心思想是**"谁用谁存"**，把优化器状态、梯度和参数分散到不同 GPU，消除冗余存储。

**1. ZeRO 三阶段对比：**

| 阶段 | 切分对象 | 显存节省 | 通信开销 |
|------|----------|----------|----------|
| **ZeRO-1** | 仅优化器状态 | 4× | 与数据并行相同 |
| **ZeRO-2** | 优化器状态 + 梯度 | 8× | 与数据并行相同 |
| **ZeRO-3** | 优化器状态 + 梯度 + **参数** | 与数据并行度 Nd 线性相关 | 增加参数 all-gather |

**2. 扩展技术：**

| 技术 | 原理 | 适用场景 |
|------|------|----------|
| **ZeRO-Offload** | 将优化器状态和计算卸载到 CPU 内存 + NVMe SSD | 单卡可训百亿模型 |
| **ZeRO-Infinity** | 扩展 Offload，支持 GPU、CPU、NVMe 三级存储 | 无限扩展超大模型 |

**3. ZeRO-3 的参数切片细节：**
前向/反向传播时，各 GPU 按需通过 `all-gather` 收集所需参数分片，计算完即释放。配合 Activation Checkpointing 可进一步降低激活值显存。

**4. 与其他优化技术的协同：**

| 技术 | 原理 | 效果 |
|------|------|------|
| 混合精度训练（FP16/BF16） | 前向/反向用 FP16，优化器用 FP32 | 参数/梯度显存减半 |
| 梯度累积 | 用小 batch 模拟大 batch | 减少激活值峰值 |
| Activation Checkpointing | 只存关键层激活，其余重算 | 以 20%-30% 计算换显存 |
| 流水线并行（PP） | 不同层放不同 GPU | 每卡只存部分层参数 |
| 张量并行（TP） | 单层内部分割（如列/行切分） | 单卡存更少参数 |

**5. 显存公式（启用 ZeRO-Offload）：**
单卡显存需求 ≈ 16Φ/Nd + activations + buffer

**6. 实际使用建议：**

| 模型规模 | 推荐配置 |
|----------|----------|
| < 1B，单卡可放下 | 直接使用 FP16 |
| 1B ~ 10B，多卡可用 | ZeRO-2 + Activation Checkpointing |
| 10B ~ 100B | ZeRO-3 + Offload（CPU）|
| 100B+ | ZeRO-Infinity（NVMe）+ 3D 并行 |

## 数据并行（Data Parallelism, DP）

> 来源：2026-04-18 对话归档

**问题/场景：**
如何理解分布式训练中最基础的数据并行，以及它与 DeepSpeed ZeRO 的关系。

**核心知识点：**
数据并行是**最基础、最常用**的分布式训练方式。核心思路：**每个 GPU 都存一份完整的模型，但输入数据被切成 N 份，各 GPU 独立计算，最后把梯度汇总同步。**

**1. 工作流程：**

| 步骤 | 各 GPU 行为 |
|------|------------|
| 1. 分发数据 | 全局 Batch 被切成 N 份，每卡拿到一份 |
| 2. 独立前向传播 | 每卡用自己的数据计算 loss |
| 3. 独立反向传播 | 每卡计算出各自的梯度 |
| 4. 梯度同步（All-Reduce） | 各卡梯度求平均，保证参数更新一致 |
| 5. 更新参数 | 每卡用同步后的梯度各自更新（结果相同）|

**2. 关键的通信操作：All-Reduce**
- Ring-AllReduce：把 N 个 GPU 排成环，梯度分块传递，总通信量约 2 × 模型大小
- 本质：每张卡最终得到所有卡梯度的平均值 (1/N)Σgi

**3. 数据并行 vs 其他并行方式：**

| 并行方式 | 切分对象 | 每卡存多少模型 | 适用场景 |
|----------|----------|----------------|----------|
| **数据并行（DP）** | **数据** | 100% 完整模型 | 模型能放进单卡时，最省心 |
| **模型并行（MP）** | **模型参数** | 部分层/参数 | 模型太大，单卡放不下 |
| **流水线并行（PP）** | **网络层** | 若干连续层 | 层数很多的大模型 |
| **张量并行（TP）** | **单层内的张量** | 单层的一部分 | 单层参数量过大 |
| **ZeRO** | 数据 + 优化器状态 + 梯度 + 参数 | 按需动态收集 | 超大模型训练 |

**4. 数据并行的致命前提与问题：**
- **前提**：模型必须能完整放进单张 GPU
- 7B 模型用 FP16 需 14GB 存参数，但加上梯度 + Adam 状态需 ~112GB，远超 A100 80GB 上限 → **传统 DP 直接失效**

**5. DeepSpeed ZeRO 与数据并行的关系：**
- **ZeRO 本质上是一种"升级版的分布式数据并行"（DDP）**
- 仍然基于数据并行的思想（数据切分、独立计算），但通过把模型状态也分布式存储，突破了"单卡必须装下整个模型"的瓶颈

| | 传统 DP | ZeRO |
|--|---------|------|
| 模型存储 | 每卡存完整模型 | 参数/梯度/优化器状态 **切分到各卡** |
| 通信量 | 仅 All-Reduce 梯度 | All-Reduce + All-Gather + Reduce-Scatter |
| 显存效率 | O(Φ) 每卡 | O(Φ/N) 每卡 |
| 代码改动 | 几乎无 | 几乎无（DeepSpeed 封装）|
