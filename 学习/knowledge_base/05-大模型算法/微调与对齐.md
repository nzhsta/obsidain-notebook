# 微调与对齐

## Agent 微调 tool_call 数据格式

> 来源：2026-04-17 对话归档

**问题/场景：**
用户询问大模型 Agent 微调中 tool_call 的对话数据应该是什么样的，以及不同框架的格式差异。

**核心知识点：**
- Agent 微调的目标是让模型学会：何时调用工具、调用什么工具、传什么参数、如何整合工具返回结果
- 对话数据采用 ChatML 格式，关键角色：`system`（定义工具）、`user`（请求）、`assistant`（tool_call 或最终回答）、`tool`（工具返回结果）
- 业界主流格式分为三大类：结构化 JSON 字段（OpenAI/Qwen/GLM）、纯文本 ReAct、XML-like 标签（Llama 3.1+）

**OpenAI 原生格式：**
```json
{
  "messages": [
    { "role": "system", "content": "You have access to tools..." },
    { "role": "user", "content": "北京天气怎么样？" },
    {
      "role": "assistant",
      "content": null,
      "tool_calls": [
        {
          "id": "call_1",
          "type": "function",
          "function": {
            "name": "get_weather",
            "arguments": "{\"location\": \"北京\"}"
          }
        }
      ]
    },
    { "role": "tool", "tool_call_id": "call_1", "content": "{\"temperature\": 22}" },
    { "role": "assistant", "content": "北京今天气温 22°C。" }
  ]
}
```

**ReAct 格式（纯文本）：**
```text
Thought: 用户问北京天气，需要调用 get_weather
Action: get_weather
Action Input: {"location": "北京"}
Observation: {"temperature": 22}
Thought: 已拿到结果，可以给出最终回答
Final Answer: 北京今天气温 22°C。
```

**Llama 3.1+ XML 格式：**
```xml
<tool_call>
{"name": "get_weather", "arguments": {"location": "北京"}}
</tool_call>
```

**各格式对比：**

| 格式 | 代表模型/框架 | 工具声明位置 | 调用表达方式 | 微调难度 |
|------|-------------|------------|-----------|---------|
| OpenAI tool_calls | GPT-4、Claude、Qwen2.5 | tools 参数 / system prompt | 结构化 JSON 字段 | 低 |
| ReAct | 早期开源模型、LangChain | system prompt 文本描述 | 纯文本 Thought/Action/Observation | 中（文本长） |
| Qwen 原生 | Qwen2、Qwen2.5 | system prompt + 特殊 token | tool_calls JSON | 低 |
| GLM-4 | ChatGLM4 | system prompt | metadata.tool_calls | 低 |
| Llama XML | Llama 3.1+ | 系统 prompt 中的 tool 列表 | <function=xxx> 或 <tool_call> 标签 | 中 |

**关键注意点：**
- tool_calls 中每个调用必须有唯一 id，tool 角色返回时通过 tool_call_id 对应
- arguments 必须是合法 JSON 字符串，不是对象
- ReAct 通用性最强，但输出冗长、解析容易出错
- Llama Factory 等工具支持通过配置 `tool_format: default/glm4/llama3` 自动转换数据格式
